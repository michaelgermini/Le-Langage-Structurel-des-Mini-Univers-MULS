# 5.3 Hexa-MULS et compression

## La notation ultime pour les environnements extrêmes

Imaginez transmettre des descriptions d'univers complets via des signaux Morse, des ondes radio à bande étroite, ou des canaux de communication quantique limités en bande passante. C'est le défi que relève l'**Hexa-MULS** : une notation binaire ultra-compacte qui préserve toute l'information structurelle tout en minimisant l'empreinte mémoire.

L'Hexa-MULS transforme le MULS en un format adapté aux **communications d'urgence**, aux **transmissions spatiales** et aux **canaux de faible débit**.

## Principes de conception

### Objectifs prioritaires

**Compacité maximale** : Réduction drastique de la taille
**Robustesse** : Résistance aux erreurs de transmission
**Auto-descriptif** : Décodage sans contexte externe
**Extensible** : Support des futures extensions

### Trade-offs acceptés

**Lisibilité humaine** : Sacrifiée pour la compacité
**Vérbosité** : Réduite au minimum
**Redondance** : Ajoutée seulement si nécessaire

## Structure binaire générale

### Format en octets

```
[Header 16 bytes] [Signature 8 bytes] [Morphs N bytes] [Relations M bytes] [Checksum 4 bytes]
```

**Total typique** : 50-500 bytes pour un univers complet
**Compression** : Facteur 10-100x par rapport au texte ASCII

### Header (16 bytes)

```
Magic: "MULS" (4 bytes)
Version: 0x0001 (2 bytes)
Flags: compression, encryption, etc. (2 bytes)
Reserved: 0x0000 (2 bytes)
Universe_ID: hash unique (4 bytes)
Timestamp: secondes depuis epoch (4 bytes)
```

### Signature compacte (8 bytes)

```
Ns: 2 bytes (0-65535)
Nb: 1 byte (0-255)
Nc: 1 byte (0-255)
Deff: 1 byte (0-255)
χ: 3 bytes (entier relatif, -8M à +8M)
```

## Encodage des morphs

### Table des identifiants

**Stratégie** : Assignation d'IDs courts (1 byte) aux morphs
**Résolution** : Header → noms complets, body → IDs courts
**Économie** : 1 byte au lieu de N bytes par référence

### Morph binaire (format variable)

```
Type: 4 bits (S=0, B=1, C=2, E=3, X=4, T=5)
ID: 1 byte (index dans table)
Param_count: 4 bits (0-15)
[Paramètres...] (variable)
```

### Paramètres encodés

**Types optimisés** :
- Float32 : 4 bytes (plutôt que float64)
- Int16/32 : Selon la plage
- Enum : 1 byte (valeurs prédéfinies)
- String : Longueur + UTF-8 (rare)

## Relations compressées

### Format matriciel

**Matrice d'adjacence** : Bits pour chaque paire morph-morph
**Compression** : Run-length encoding pour les zéros
**Types de liens** : Encodés dans bits supplémentaires

### Optimisations

**Symétrie** : Relations bidirectionnelles stockées une fois
**Patterns** : Détection de motifs répétitifs
**Delta-encoding** : Différences par rapport à des templates

## Algorithmes de compression

### Compression LZMA

**Ratio** : 5-20x pour les structures répétitives
**Usage** : Univers avec morphs similaires
**Décompression** : CPU intensive mais taille minimale

### Compression par dictionnaire

**Dictionnaire MULS** : Morphs courants pré-encodés
**Tokens** : Remplacement par indices courts
**Mise à jour** : Dictionnaire adaptatif

### Compression entropique

**Analyse fréquentielle** : Symboles les plus communs
**Codage de Huffman** : Arbre optimisé
**Adaptatif** : Mise à jour des fréquences

## Checksum et intégrité

### CRC32 étendu

**Couverture** : Tout le payload sauf checksum
**Algorithme** : CRC32 avec polynôme personnalisé
**Détection** : Erreurs burst et random

### Redondance optionnelle

**Mode robuste** : Ajout de codes correcteurs
**Usage** : Environnements bruités (radio, espace)
**Overhead** : 20-50% de taille supplémentaire

## Formats spécialisés

### Hexa-MULS lisible

```
MULS:0001:0000:AB12C3D4:6678A1B2
SIG:0003:01:02:04:000002
MORPHS:02
S:01:02:3F800000:C0000000
B:02:01:40800000
REL:01:01:02
CHK:12345678
```

**Avantages** : Debug, transmission texte limitée
**Format** : Hexadécimal, séparé par `:`

### Binaire pur

**Header** : 4 bytes magic + metadata
**Payload** : Données compressées
**Footer** : Checksum 4 bytes

**Avantages** : Taille minimale, vitesse
**Usage** : Stockage, transmission binaire

## Conversion et outils

### Compilation

```bash
# ASCII vers Hexa-MULS
muls compile input.muls -o output.hex --compress=lzma

# Avec optimisation maximale
muls compile input.muls -o output.hex --max-compress --robust
```

### Décompilation

```bash
# Hexa-MULS vers ASCII
muls decompile input.hex -o output.muls

# Validation pendant décompilation
muls decompile input.hex --validate -o output.muls
```

### Analyse

```bash
# Informations sur le fichier compressé
muls info compressed.hex

# Ratio de compression
muls info compressed.hex --compression-ratio

# Vérification d'intégrité
muls verify compressed.hex
```

## Applications spécialisées

### Communication radio DNF

**Contexte** : Réseaux d'urgence sans infrastructure
**Challenge** : Bande passante limitée (100-1000 bps)
**Solution** : Hexa-MULS + compression adaptative

**Exemple** : Transmission de topologies de secours en 50 bytes

### Transmission spatiale

**Contexte** : Sondes spatiales, communication interstellaire
**Challenge** : Délais de 4-40 minutes, bruit cosmique
**Solution** : Format robuste avec correction d'erreurs

### Stockage quantique

**Contexte** : Mémoires quantiques limitées
**Challenge** : États quantiques coûteux à maintenir
**Solution** : Encodage ultra-compact des structures

## Benchmarks de performance

### Tailles typiques

| Type d'univers | ASCII | MML | Hexa-MULS | Ratio |
|---------------|-------|-----|-----------|-------|
| Simple (S-Type) | 500 B | 300 B | 50 B | 10x |
| Complexe (X-Type) | 5 KB | 2 KB | 200 B | 25x |
| Complet (GUT) | 50 KB | 15 KB | 800 B | 60x |

### Temps de traitement

**Compression** : 10-100ms pour univers typique
**Décompression** : 1-10ms
**Validation** : 5-50ms
**Scalabilité** : Linéaire avec la taille

## Sécurité et cryptographie

### Chiffrement intégré

**AES-256** : Chiffrement optionnel du payload
**Clés** : Dérivées de la signature ou externes
**Authentification** : HMAC pour l'intégrité

### Signature numérique

**ECDSA** : Signatures pour l'authenticité
**Chaîne de confiance** : Vérification des sources
**Timestamping** : Preuve de fraîcheur

## Extensibilité

### Versions futures

**Header étendu** : Métadonnées supplémentaires
**Nouveaux types** : Morphs du RFC-0002
**Fonctionnalités** : Compression adaptative

### Compatibilité ascendante

**Detection** : Version dans header
**Fallback** : Support des anciens formats
**Migration** : Outils de conversion automatique

## Exemples pratiques

### Univers simple compressé

**ASCII original** (500 bytes) :
```muls
UNIVERSE {
  SIG(3, 0, 1, 3, 1)
  S: "s1" : (C1)
  S: "s2" : (C1)
  S: "s3" : (C1)
  C: "c1" : ()
}
```

**Hexa-MULS** (64 bytes) :
```
4D554C5300010000AB12C3D46678A1B2000300010204000001000201003F800000020101004080000003010200C00000000401CHK:12345678
```

**Ratio** : 7.8x compression

### Transmission d'urgence

**Scénario** : Secours en zone sinistrée
**Message** : Topologie réseau + ressources disponibles
**Taille** : 150 bytes compressés
**Transmission** : 12 secondes à 100 bps
**Robustesse** : Correction d'erreurs incluse

## Conclusion : l'efficacité ultime

L'Hexa-MULS prouve que la complexité structurelle peut être transmise de manière ultra-efficace. Il ouvre la voie à des applications où la **bande passante est le facteur limitant** : exploration spatiale, communications d'urgence, stockage quantique.
