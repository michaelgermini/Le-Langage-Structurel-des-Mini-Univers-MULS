# 5.1 Format compact MULS/ASCII

## La notation lisible par humains et machines

Imaginez un langage de programmation où le code serait à la fois élégant à lire pour les développeurs et optimisé pour l'analyse automatique. C'est exactement l'objectif du **format compact MULS/ASCII** : une notation textuelle qui équilibre lisibilité humaine et traitement machine efficace.

Ce format est le "visage public" du MULS - ce que voient les chercheurs, ce qui est publié dans les articles, ce qui est enseigné dans les cours.

## Structure générale

### Format canonique

```
UNIVERSE {
  SIG(Ns,Nb,Nc,Deff,χ)
  morph_definitions...
}
```

### Éléments obligatoires

- **UNIVERSE** : Mot-clé ouvrant (en majuscules)
- **{ }** : Délimiteurs de bloc
- **SIG(...)** : Signature topologique
- **Au moins un morph** : Définition structurelle

## Syntaxe des morphs

### Format de base

```
Type: "identifiant" : (paramètres)
```

### Composants

**Type** : S, B, C, E, X, T (majuscule)
**Identifiant** : Chaîne entre guillemets
**Paramètres** : Liste entre parenthèses, séparés par virgules

### Exemples

```muls
S: "electron" : (mass=0.511, charge=-1)
B: "our_brane" : (dimension=4, tension=1.0)
C: "compact_dim" : (radius=1e-35, topology="torus")
E: "entanglement" : (S1, S2, purity=0.95)
X: "interaction" : (S1, S2, B1, strength=0.1)
T: "topology" : (genus=1, orientable=true)
```

## Paramètres et valeurs

### Types de valeurs

**Numériques** :
- Entiers : `42`, `-7`
- Flottants : `3.14`, `1e-35`, `6.022e23`

**Chaînes** :
- Simples : `"electron"`
- Avec espaces : `"weak interaction"`

**Booléens** : `true`, `false`

**Listes** : `[1, 2, 3]`, `["x", "y", "z"]`

**Nuls** : `null` (pour paramètres optionnels)

### Notation scientifique

**Formats supportés** :
- `1.23e-45`
- `6.67430e-11`
- `1.602176634e-19`

### Constantes prédéfinies

**Physiques** :
- `PLANCK_LENGTH = 1.616255e-35`
- `SPEED_OF_LIGHT = 299792458`
- `GRAVITATIONAL_CONSTANT = 6.67430e-11`

**Mathématiques** :
- `PI = 3.141592653589793`
- `E = 2.718281828459045`

## Relations et connexions

### Format simple

```
morph : (cible1, cible2, ...)
```

### Relations paramétrées

```
morph : (cible1(strength=0.8), cible2)
```

### Relations multiples

```
morph : (
  cible1,
  cible2(type="vibrational"),
  cible3
)
```

### Auto-références (avec précaution)

```
S: "self_interacting" : (S1)  // Référence à soi-même
```

## Commentaires et documentation

### Commentaires de ligne

```
S: "electron" : (mass=0.511)  // Particule élémentaire
```

### Commentaires de bloc

```
/*
 * Modèle standard des particules
 * Version simplifiée
 */
UNIVERSE {
  SIG(6, 1, 3, 4, 2)
  // Définitions...
}
```

### Documentation inline

```
S: "quark_up" : (
  mass=0.002,     // Masse en GeV
  charge=2/3,     // Charge électrique
  color="red"     // Charge de couleur
)
```

## Formatage et style

### Indentation

**Recommandé** : 2 espaces par niveau
**Minimum** : 1 espace ou tabulation
**Maximum** : 4 espaces (pour lisibilité)

### Sauts de ligne

**Après chaque morph** : Oui
**À l'intérieur des paramètres** : Optionnel pour lisibilité

```muls
// Style compact
S: "electron" : (mass=0.511, charge=-1)

// Style étendu
S: "electron" : (
  mass=0.511,
  charge=-1,
  spin=1/2
)
```

### Longueur des lignes

**Recommandé** : ≤ 80 caractères
**Maximum** : ≤ 120 caractères
**Rupture** : Après opérateurs ou virgules

## Optimisations de lisibilité

### Groupement logique

```muls
// Cordes élémentaires
S: "electron" : (mass=0.511, charge=-1)
S: "muon" : (mass=0.106, charge=-1)
S: "tau" : (mass=1.777, charge=-1)

// Brane visible
B: "standard_model" : (S1, S2, S3, dimension=4)

// Dimensions compactifiées
C: "su2" : (radius=1e-35)
C: "su3" : (radius=1e-35)
C: "u1" : (radius=1e-35)
```

### Séparation sémantique

```muls
// ========================================
// Modèle du Standard avec dimensions extra
// ========================================

UNIVERSE {
  SIG(16, 2, 7, 10, -200)

  // Particules du Standard
  // ---------------------

  // Particules élémentaires
  // ---------------------

  // ... définitions ...

  // Interactions
  // -----------

  // ... définitions ...

  // Géométrie
  // ---------

  // ... définitions ...
}
```

## Gestion des erreurs de formatage

### Correction automatique

Le parser MULS peut corriger :

**Indentation** : Normalisation automatique
**Espaces** : Ajout/suppression autour des opérateurs
**Sauts de ligne** : Insertion aux bons endroits

### Validation de style

**Outil** : `muls format --check file.muls`
**Rapport** : Violations des conventions de style
**Correction** : `muls format --fix file.muls`

## Exemples complets

### Univers simple (S-Type)

```muls
UNIVERSE {
  SIG(3, 0, 1, 3, 1)

  // Trois cordes dans une dimension compactifiée
  S: "string1" : (frequency=440, C1)
  S: "string2" : (frequency=550, C1)
  S: "string3" : (frequency=660, C1)

  // Dimension compactifiée
  C: "compact" : (radius=1.616e-35, topology="circle")
}
```

### Univers complexe (X-Type)

```muls
UNIVERSE {
  SIG(12, 3, 6, 10, -144)

  /*
   * Modèle GUT avec branes et dimensions extra
   */

  // Particules du Standard (simplifiées)
  S: "quark_u" : (mass=0.002, charge=2/3, B1)
  S: "quark_d" : (mass=0.005, charge=-1/3, B1)
  S: "electron" : (mass=0.511, charge=-1, B1)
  S: "neutrino" : (mass=0, charge=0, B1)

  // Bosons de jauge
  S: "photon" : (mass=0, charge=0, B1)
  S: "w_boson" : (mass=80.4, B1)
  S: "z_boson" : (mass=91.2, B1)
  S: "gluon" : (mass=0, B1)

  // Higgs (simplifié)
  S: "higgs" : (mass=125, B1)

  // Particules supersymétriques (au-delà du Standard)
  S: "neutralino" : (mass=100, B2)
  S: "squark" : (mass=500, B2)
  S: "slepton" : (mass=150, B2)

  // Branes
  B: "visible_sector" : (
    dimension=4,
    tension=1.0,
    S1, S2, S3, S4, S5, S6, S7, S8, S9
  )
  B: "hidden_sector" : (dimension=6, S10, S11, S12)
  B: "bulk" : (dimension=10)

  // Dimensions compactifiées (Calabi-Yau simplifié)
  C: "complex1" : (h11=3, h21=67, radius=1e-35)
  C: "complex2" : (h11=2, h21=86, radius=1e-35)
  C: "complex3" : (h11=1, h21=39, radius=1e-35)
  C: "real1" : (topology="torus", radius=1e-35)
  C: "real2" : (topology="torus", radius=1e-35)
  C: "real3" : (topology="torus", radius=1e-35)

  // Intrications
  E: "ew_symmetry_breaking" : (S5, S6, S7, purity=0.99)
  E: "supercritical" : (S10, S11, S12)

  // Interactions multiples
  X: "strong_force" : (S1, S2, S8, strength=1.0)
  X: "electroweak" : (S3, S4, S5, S6, S7, strength=0.1)
  X: "gravity" : (B1, B2, B3, universal=true)

  // Topologie
  T: "calabi_yau" : (genus=3, orientable=true, χ=-144)
}
```

## Conversion et interopérabilité

### Vers autres formats

**MML** : `muls convert ascii-to-mml file.muls`
**JSON** : `muls convert ascii-to-json file.muls`
**Binary** : `muls convert ascii-to-binary file.muls`

### Validation croisée

**Test** : Conversion A→B→A préserve la structure
**Outil** : `muls validate --roundtrip file.muls`

## Conclusion : l'équilibre parfait

Le format compact MULS/ASCII offre le meilleur des deux mondes : une **lisibilité exceptionnelle** pour les humains et une **structure rigoureuse** pour les machines. Il est le format de référence pour l'écriture, la lecture et l'enseignement du MULS.

Dans le chapitre suivant, nous explorerons le format MML (MULS Markup Language), optimisé pour la transmission et le stockage efficace.

*"La beauté de l'ASCII réside dans sa simplicité ; sa puissance dans sa rigueur."*
