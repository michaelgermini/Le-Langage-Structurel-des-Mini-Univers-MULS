# 5.2 Format transmissible MML

## Le XML du MULS : optimisé pour l'échange et l'interopérabilité

Si le format ASCII est le langage naturel du MULS, le **MML (MULS Markup Language)** en est la version formelle et structurée. Inspiré du XML, le MML est conçu pour la **transmission fiable**, le **stockage durable** et l'**interopérabilité** entre systèmes différents.

Il sacrifie un peu de lisibilité humaine pour gagner en robustesse machine et en efficacité de transmission.

## Structure XML-like

### Format canonique

```xml
<universe signature="SIG(3,1,2,4,2)">
  <morphs>
    <string id="electron" mass="0.511" charge="-1">
      <relations>
        <relation target="brane1" type="confinement"/>
      </relations>
    </string>
    <brane id="brane1" dimension="4" tension="1.0">
      <relations>
        <relation target="electron" type="contains"/>
      </relations>
    </brane>
  </morphs>
</universe>
```

### Éléments principaux

**`<universe>`** : Élément racine
- Attribut `signature` : Signature topologique obligatoire

**`<morphs>`** : Conteneur pour tous les morphs

**`<string>`**, `<brane>`**, etc.** : Éléments pour chaque type de morph

## Éléments morphologiques

### Cordes (Strings)

```xml
<string id="electron"
        mass="0.511"
        charge="-1"
        spin="0.5"
        frequency="440">
  <relations>
    <relation target="brane1" strength="1.0"/>
    <relation target="compact1" coupling="0.1"/>
  </relations>
</string>
```

**Attributs standards** :
- `id` : Identifiant unique (requis)
- `mass`, `charge`, `spin` : Propriétés physiques
- `frequency`, `tension` : Propriétés vibrationnelles

### Branes

```xml
<brane id="visible_sector"
       dimension="4"
       tension="1.0"
       charge="0"
       orientation="timelike">
  <relations>
    <relation target="electron"/>
    <relation target="proton"/>
  </relations>
</brane>
```

**Attributs spécifiques** :
- `dimension` : Dimensionalité (3-10 typiquement)
- `tension` : Tension de la brane
- `orientation` : Timelike/spacelike/lightlike

### Dimensions compactifiées

```xml
<compact id="su3"
         radius="1.616e-35"
         topology="sphere"
         cohomology="h11=1,h21=0">
  <relations>
    <relation target="quark1" mode="fundamental"/>
  </relations>
</compact>
```

**Attributs topologiques** :
- `topology` : Type géométrique
- `cohomology` : Classes de Chern
- `moduli` : Paramètres de forme

### Liens d'intrication

```xml
<entanglement id="bell_pair"
              type="EPR"
              purity="0.999"
              fidelity="0.985">
  <relations>
    <relation target="particle1"/>
    <relation target="particle2"/>
  </relations>
</entanglement>
```

**Attributs quantiques** :
- `purity` : Pureté de l'état (0-1)
- `fidelity` : Fidélité par rapport à l'état cible
- `concurrence` : Mesure d'intrication

### Interactions multiples

```xml
<interaction id="strong_force"
             type="gauge"
             group="SU(3)"
             coupling="1.2">
  <participants>
    <participant target="quark1" representation="fundamental"/>
    <participant target="quark2" representation="fundamental"/>
    <participant target="gluon" representation="adjoint"/>
  </participants>
</interaction>
```

**Attributs de groupe** :
- `group` : Groupe de jauge
- `representation` : Représentation des particules
- `coupling` : Constante de couplage

## Système de relations

### Format standard

```xml
<relations>
  <relation target="morph_id"
            type="vibrational"
            strength="0.8"
            phase="0"/>
</relations>
```

### Types de relations

**Structurelles** :
- `confinement` : Morph confiné sur une brane
- `compactification` : Vibration sur dimension compactifiée
- `entanglement` : Connexion quantique

**Physiques** :
- `gauge` : Interaction de jauge
- `yukawa` : Couplage de masse
- `gravitational` : Attraction gravitationnelle

**Topologiques** :
- `homotopy` : Classes d'homotopie
- `cohomology` : Classes de cohomologie
- `ktheory` : Classes K-théoriques

## Métadonnées et annotations

### Informations de version

```xml
<universe signature="SIG(3,1,2,4,2)"
           version="RFC-0001"
           created="2024-11-19"
           author="MULS Consortium">
```

### Commentaires et documentation

```xml
<!-- Modèle simplifié du Standard -->
<universe signature="SIG(16,1,3,4,2)">
  <description>
    Modèle standard des particules avec une brane visible
    et trois dimensions compactifiées.
  </description>
```

### Références externes

```xml
<reane id="our_universe">
  <references>
    <arxiv id="hep-th/0502058"/>
    <doi id="10.1103/PhysRevD.71.086004"/>
  </references>
</brane>
```

## Optimisations pour la transmission

### Compression automatique

**Éléments vides** : Auto-fermeture
```xml
<string id="photon" mass="0" charge="0"/>
```

**Attributs par défaut** : Omis s'ils sont standards
**Normalisation** : Valeurs arrondies pour transmission

### Format binaire équivalent

Pour les transmissions très contraintes :

**Header** : Signature et métadonnées
**Body** : Morphs encodés en binaire
**Footer** : Checksum de validation

## Validation et schémas

### Schéma XML

```xml
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="universe">
    <xs:complexType>
      <xs:attribute name="signature" type="xs:string" use="required"/>
      <xs:element name="morphs" minOccurs="1" maxOccurs="1">
        <!-- Définition des morphs -->
      </xs:element>
    </xs:complexType>
  </xs:element>
</xs:schema>
```

### Validation automatique

**Outil** : `xmllint --schema muls.xsd file.mml`
**Rapport** : Conformité au schéma officiel
**Correction** : Suggestions de réparation

## Conversion entre formats

### ASCII vers MML

```bash
muls convert ascii-to-mml input.muls > output.mml
```

### MML vers ASCII

```bash
muls convert mml-to-ascii input.mml > output.muls
```

### Validation de la conversion

```bash
muls validate --roundtrip file.muls  # Test A→MML→A
```

## Exemples complets

### Univers simple

```xml
<universe signature="SIG(2,1,1,4,2)">
  <description>
    Univers simple avec 2 cordes, 1 brane, 1 dimension compactifiée
  </description>

  <morphs>
    <string id="electron" mass="0.511" charge="-1">
      <relations>
        <relation target="brane1" type="confinement"/>
      </relations>
    </string>

    <string id="photon" mass="0" charge="0">
      <relations>
        <relation target="brane1" type="propagation"/>
      </relations>
    </string>

    <brane id="visible" dimension="4" tension="1.0">
      <relations>
        <relation target="electron"/>
        <relation target="photon"/>
        <relation target="compact1" type="embedding"/>
      </relations>
    </brane>

    <compact id="extra_dim" radius="1.616e-35" topology="circle">
      <relations>
        <relation target="brane1" type="compactification"/>
      </relations>
    </compact>
  </morphs>
</universe>
```

### Univers complexe

```xml
<universe signature="SIG(12,3,6,10,-144)"
           version="RFC-0001"
           created="2024-11-19">

  <description>
    Modèle GUT complet avec secteurs visible et caché,
    supersymétrie et dimensions de Calabi-Yau
  </description>

  <morphs>
    <!-- Particules du Standard -->
    <string id="quark_u" mass="0.002" charge="0.667">
      <relations>
        <relation target="visible_brane" type="confinement"/>
        <relation target="strong_force" type="gauge"/>
      </relations>
    </string>

    <!-- Branes multiples -->
    <brane id="visible_brane" dimension="4" tension="1.0">
      <relations>
        <relation target="standard_model_particles" type="contains"/>
      </relations>
    </brane>

    <brane id="hidden_brane" dimension="6" tension="10.0">
      <relations>
        <relation target="susy_particles" type="contains"/>
      </relations>
    </brane>

    <!-- Dimensions de Calabi-Yau -->
    <compact id="cy1" topology="calabi_yau" h11="3" h21="67">
      <relations>
        <relation target="visible_brane" type="moduli"/>
      </relations>
    </compact>

    <!-- Interactions -->
    <interaction id="strong_force" group="SU(3)" coupling="1.2">
      <participants>
        <participant target="quark_u"/>
        <participant target="quark_d"/>
        <participant target="gluon"/>
      </participants>
    </interaction>

    <!-- Intrications -->
    <entanglement id="ew_symmetry" purity="0.99">
      <relations>
        <relation target="higgs"/>
        <relation target="w_boson"/>
        <relation target="z_boson"/>
      </relations>
    </entanglement>
  </morphs>
</universe>
```

## Avantages pour la transmission

### Robustesse

**Auto-descriptif** : Structure explicite
**Validable** : Schéma de validation
**Évolutif** : Nouvelles versions possibles

### Efficacité

**Parsable** : Librairies XML standard
**Compressible** : Algorithmes de compression XML
**Streamable** : Traitement incrémental possible

### Interopérabilité

**Standard** : Basé sur XML éprouvé
**Outils** : Écosystème riche
**APIs** : Interfaces de programmation standard

## Conclusion : le format professionnel

Le MML est le format de choix pour les applications sérieuses : **transmission réseau**, **stockage en base de données**, **échange inter-systèmes**. Il offre la robustesse et l'efficacité nécessaires pour les déploiements à grande échelle du MULS.
