# 4.1 Règles syntaxiques

## La grammaire formelle du langage structurel

Imaginez apprendre une nouvelle langue. Au début, vous devez maîtriser les règles de base : comment former des phrases, accorder les verbes, placer les mots. Même si vous ne comprenez pas encore le sens profond, vous pouvez reconnaître si une phrase est grammaticalement correcte.

Les **règles syntaxiques** du MULS jouent exactement ce rôle : elles définissent la **structure formelle** des descriptions d'univers, indépendamment de leur signification physique. Elles garantissent que toute expression MULS est bien formée, comme une phrase grammaticalement correcte.

## Structure générale d'un univers MULS

### Format canonique

Tout univers MULS suit cette structure :

```
UNIVERSE {
  SIG(signature)
  structure_1
  structure_2
  ...
  structure_n
}
```

### Composants obligatoires

**UNIVERSE** : Mot-clé ouvrant la définition
**{ }** : Délimiteurs de bloc
**SIG(signature)** : Signature topologique obligatoire
**structures** : Au moins une structure morphologique

## Syntaxe des morphs

### Format général d'un morph

Chaque morph suit le pattern :

```
TYPE(paramètres) : relations
```

### Types de morphs valides

**S** : Corde - `S(id, paramètres)`
**B** : Brane - `B(id, paramètres)`
**C** : Dimension compactifiée - `C(id, paramètres)`
**E** : Lien d'intrication - `E(id, paramètres)`
**X** : Interaction multiple - `X(id, paramètres)`
**T** : Topologie - `T(id, paramètres)`

### Identifiants

Règles pour les identifiants :

**Format** : Lettre suivie de lettres/chiffres/underscore
**Longueur** : 1-32 caractères
**Sensibilité** : Non sensible à la casse (S1 ≡ s1)
** Unicité** : Chaque identifiant unique dans l'univers

### Paramètres

Format des paramètres :

**Syntaxe** : `nom=valeur` séparés par des virgules
**Types** : nombres, chaînes, booléens, listes
**Exemples** :
- `frequency=440`
- `topology="torus"`
- `compactified=true`
- `dimensions=[3,7,11]`

## Syntaxe des relations

### Format général des relations

Les relations suivent :

```
morph : relation_list
```

Où `relation_list` est une liste de cibles séparées par des virgules.

### Types de relations

**Connexion simple** : `S1`
**Connexion paramétrée** : `S1(strength=0.8)`
**Relation multiple** : `(S1, S2, B1)`
**Relation vide** : `()`

### Expressions complexes

**Imbrication** : `S1(S2(B1))`
**Listes** : `[S1, S2, S3]`
**Ensembles** : `{S1, S2}`

## Syntaxe de la signature

### Format obligatoire

```
SIG(Ns, Nb, Nc, Deff, χ)
```

Où :
- **Ns** : Nombre entier ≥ 0 (cordes)
- **Nb** : Nombre entier ≥ 0 (branes)
- **Nc** : Nombre entier ≥ 0 (dimensions compactifiées)
- **Deff** : Nombre entier > 0 (dimensions effectives)
- **χ** : Nombre entier (caractéristique d'Euler)

### Contraintes

**Cohérence** : Deff ≥ 3 (dimensions spatiales + temps)
**Minimalité** : Pas de zéros inutiles
**Validité** : χ doit être compatible avec la topologie

## Règles de formatage

### Espaces et indentation

**Recommandé** : Indentation de 2 espaces par niveau
**Obligatoire** : Sauts de ligne après chaque structure
**Optionnel** : Espaces autour des opérateurs

### Commentaires

**Ligne** : `// commentaire`
**Bloc** : `/* commentaire */`
**Emplacement** : N'importe où sauf au milieu d'un token

### Points-virgules

**Optionnels** : À la fin des déclarations
**Recommandés** : Pour la clarté

## Expressions spéciales

### Constantes prédéfinies

**Mathématiques** : `PI`, `E`, `PLANCK_LENGTH`
**Physiques** : `SPEED_OF_LIGHT`, `GRAVITATIONAL_CONSTANT`
**Structurelles** : `SPHERE`, `TORUS`, `CALABI_YAU`

### Opérateurs

**Arithmétiques** : `+`, `-`, `*`, `/`, `%`
**Comparaisons** : `==`, `!=`, `<`, `>`, `<=`, `>=`
**Logiques** : `&&`, `||`, `!`
**Structurels** : `->` (relation dirigée), `<->` (bidirectionnelle)

### Fonctions built-in

**Mathématiques** : `sqrt()`, `log()`, `sin()`, `cos()`
**Structurelles** : `connect()`, `distance()`, `invariant()`
**Validation** : `validate()`, `check_consistency()`

## Règles de portée et visibilité

### Portée globale

Tous les morphs sont visibles dans tout l'univers.

### Références forward

Possibilité de référencer des morphs définis plus tard :

```muls
S: "electron" : (S_later)  // Référence anticipée
S: "photon" : ()
```

### Résolution des noms

**Ordre** : Définition puis utilisation
**Erreur** : Référence à un morph non défini → erreur de compilation

## Extensions syntaxiques

### Macros et templates

Pour la réutilisabilité :

```muls
TEMPLATE particle(type, mass) {
  S: "${type}_mode" : (frequency=mass)
}

USE particle("electron", 0.511)
```

### Imports et modules

Structure modulaire :

```muls
IMPORT "standard_model.muls"
IMPORT "cosmology.muls" AS cosmo

EXTEND cosmo.universe
```

## Validation syntaxique

### Règles automatiques

Le parser MULS vérifie :

**Parenthèses équilibrées** : Toute `(` a sa `)`
**Blocs complets** : Tout `{` a son `}`
**Types corrects** : Paramètres du bon type
**Références valides** : Tous les identifiants existent

### Messages d'erreur

**SyntaxError** : Erreur de grammaire
**TypeError** : Type incompatible
**ReferenceError** : Identifiant non trouvé
**ConsistencyError** : Contradiction logique

## Exemples complets

### Univers simple

```muls
UNIVERSE {
  SIG(2, 0, 1, 4, 2)

  S: "fundamental_string" : (C1)
  C: "compact_dimension" : ()
}
```

### Univers complexe

```muls
UNIVERSE {
  SIG(5, 2, 3, 10, 0)

  // Cordes avec paramètres
  S: "electron" : (frequency=440, mass=0.511, C1)
  S: "photon" : (frequency=0, mass=0, C2)

  // Brane
  B: "our_universe" : (S1, S2, C3)

  // Dimensions compactifiées
  C: "extra_dim1" : (radius=1e-35)
  C: "extra_dim2" : (topology="torus")
  C: "extra_dim3" : (type="calabi_yau")

  // Intrication
  E: "quantum_entanglement" : (S1, S2)
}
```

## Implémentation informatique

### Parser formel

Le MULS utilise une grammaire formelle :

**Type** : Grammaire context-free étendue
**Outil** : Générateur de parser (ANTLR, Bison)
**Langage cible** : AST (Abstract Syntax Tree)

### Optimisations

**Lazy parsing** : Analyse à la demande
**Incremental** : Mise à jour partielle
**Parallèle** : Traitement multi-cœurs

## Conclusion : la base formelle

Les règles syntaxiques du MULS établissent un **fondement solide** pour l'expression des structures universelles. Elles garantissent que toute description MULS est non seulement lisible par les humains, mais aussi **processable par les machines**.

Dans le chapitre suivant, nous explorerons les règles sémantiques, qui donnent du sens à ces structures formelles.

*"La syntaxe sans sémantique est comme une coquille vide ; la sémantique sans syntaxe est du chaos."*
